# Aidos: веб-панель метрик и эмулятор колонки

Дата: 2026-10-05 · Статус: дизайн согласован по секциям, ждёт ревью спеки
Основа: `docs/superpowers/specs/2026-10-03-aidos-satellite-gateway-design.md` (шлюз M0–M2 реализован на ветке `zhanzh/satellite-gateway`).

## 1. Цель и рамки

**Зачем.** Видеть, как работает цепочка «колонка → шлюз → мозг → ответ», где теряется время, и проверять её без железа и без py-xiaozhi: прямо из браузера. Это витрина проекта для портфолио.

**Критерии успеха:**
- `http://127.0.0.1:8000/` открывает панель; без перезагрузки страницы она показывает в реальном времени связь шлюза с мозгом, колонки и их состояние, ленту ходов с таймингами по этапам, медиану и p95.
- Эмулятор в Chrome на Mac проводит полный ход голосом: удерживаешь кнопку, говоришь «Сағат неше?», отпускаешь → в панели появляются текст фразы и ответа, ответ звучит в браузере.
- Ход от py-xiaozhi или BOX-3 появляется в той же ленте.
- Панель и `/api/*` доступны только с localhost.

**Не входит:** авторизация панели (M3, перед VPS), хранение истории между перезапусками, графики за большие периоды, текстовый ввод в эмуляторе, запасной Opus-кодек на WASM для браузеров без WebCodecs.

## 2. Метрики

| Метрика | Где меряется | Источник |
|---|---|---|
| Длительность фразы (с) | шлюз | длина `Utterance` |
| `stt_ms` | мозг | время `transcribe` |
| `llm_ms` | мозг | время `respond` (роутер + агенты + LLM) |
| `tts_ms` | мозг | сумма времени `synthesize` по всем предложениям |
| `first_audio_ms` | шлюз | от отправки `Utterance` до первого `SpeechChunk` |
| `total_ms` | шлюз | от отправки `Utterance` до `TurnEnd` |
| длительность ответа (с), число кадров | шлюз | сумма закодированных кадров |
| ошибка хода | шлюз | `TurnEnd.error`, обрыв связи, прерывание |
| колонки: онлайн, состояние idle/listening/thinking/speaking | шлюз | автомат состояний `device.rs` |
| связь с мозгом, число переподключений | шлюз | `LinkHandle` |

**Изменение контракта** (`proto/link.proto`, обратно совместимо):
```proto
message TurnTimings { uint32 stt_ms = 1; uint32 llm_ms = 2; uint32 tts_ms = 3; }
message TurnEnd { string device_id = 1; string turn_id = 2; bool error = 3; TurnTimings timings = 4; }
```
`TurnRunner` заполняет `timings` во всех ветках, включая ошибочные: этапы, до которых ход не дошёл, равны 0.

## 3. Архитектура шлюза

Новый модуль `gateway/src/metrics.rs`:
- `MetricsHub`: общее состояние за `Arc`. Внутри кольцевой буфер последних 100 ходов (`TurnRecord`), карта колонок (`device_id → состояние, онлайн, последнее изменение`), статус связи и счётчик переподключений, `tokio::sync::broadcast::Sender<DashEvent>` (ёмкость 256) для живых подписчиков.
- `TurnRecord { turn_id, device_id, started_at (unix ms), utterance_secs, transcript, reply_text (склейка предложений), stt_ms, llm_ms, tts_ms, first_audio_ms, total_ms, reply_secs, status: ok|error|aborted }`.
- `DashEvent` (JSON с полем `type`): `turn_started`, `transcript`, `speech`, `turn_end`, `device`, `link`.
- Агрегаты (`summary()`): число ходов, ошибок, медиана и p95 по `stt_ms`, `llm_ms`, `tts_ms`, `first_audio_ms`, `total_ms` по последним 100 успешным ходам. Это чистые функции, тестируются отдельно.

Точки записи:
- `device.rs`: смена состояния, отправка фразы (`turn_started`), `Transcript`, каждый `SpeechChunk`, `TurnEnd` или прерывание (`turn_end`), подключение и отключение колонки.
- `link.rs`: связь поднялась или упала (`LinkHandle` получает `Option<MetricsHub>`; без него, как в тестах link, работает как раньше).

Новые HTTP-маршруты в `server.rs` (все проверяют, что адрес клиента loopback, иначе 403; сервер запускается через `into_make_service_with_connect_info::<SocketAddr>()`):
- `GET /` → страница панели (`include_str!("../web/index.html")`), `GET /app.js`, `GET /app.css` с правильными `Content-Type`.
- `GET /api/state` → `{ link, devices[], turns[], summary }`.
- `GET /api/events` → SSE (`axum::response::sse`): каждый `DashEvent` отдельным событием, keep-alive раз в 15 с. При отставании подписчика (`RecvError::Lagged`) отправляется событие `resync`, и клиент перечитывает `/api/state`.
- `GET /api/emulator` → `{ device_id, token, ws_url }`.

**Эмулятор-устройство.** При старте шлюз добавляет в allowlist устройство `GATEWAY_EMULATOR_DEVICE` (по умолчанию `web-emulator`) со случайным токеном из 32 байт. Пустое значение переменной отключает эмулятор. Браузер не умеет передавать заголовок `Authorization` при открытии WebSocket, поэтому `/ws` дополнительно принимает `?token=` в query-параметре, но только для эмулятор-устройства и только с loopback-адреса. Для остальных устройств остаётся только заголовок.

## 4. Мозг (Python)

`TurnRunner.run` замеряет `time.perf_counter()` вокруг `transcribe`, `respond` и каждого `synthesize`, и отправляет `TurnEnd(timings=TurnTimings(...))`. Хелпер `_end(ids, error, timings)` получает тайминги. Сервер `BrainService` не меняется.

## 5. Веб-страница

Файлы `gateway/web/index.html`, `app.css`, `app.js`: чистые HTML, CSS и ES-модуль, без сборки, фреймворков и внешних CDN. Тёмная тема, адаптивная вёрстка (на ширине < 900 px колонки складываются в одну). Интерфейс на русском.

Блоки:
1. **Шапка:** статус связи с мозгом (зелёный или красный), число колонок онлайн, число переподключений.
2. **Цепочка:** `Колонка → VAD → STT → LLM → TTS → Колонка` на SVG. Активный этап подсвечивается по событиям: после `turn_started` идёт STT, после `transcript` — LLM, после первого `speech` — TTS и воспроизведение, после `turn_end` цепочка гаснет. Над стрелками показываются миллисекунды последнего завершённого хода.
3. **Эмулятор:** кнопка «Удерживай и говори» (мышь, касание, пробел), статус (готов / слушаю / думаю / говорю / ошибка), мини-чат «Сіз / Айдос».
4. **Сводка:** медиана и p95 по этапам, число ходов и ошибок.
5. **Колонки:** список с индикатором онлайн и текущим состоянием.
6. **Лента ходов:** новые сверху. Время, колонка, фраза → ответ, и каскадная диаграмма: STT, LLM, TTS цветными отрезками в масштабе `total_ms`, с отметкой `first_audio_ms`. Ошибки подсвечены.

Звук эмулятора:
- Вверх: `getUserMedia` (моно, без авто-усиления) → `AudioWorklet` даунсемплит до 16 кГц, кадры по 960 сэмплов → `AudioEncoder({codec:'opus', sampleRate:16000, numberOfChannels:1, bitrate:24000})`, кадр 60 мс → бинарные сообщения в `/ws`.
- Протокол: при подключении отправляется `hello` (version 1, opus 16 кГц, 60 мс); нажатие кнопки → `listen{state:start, mode:manual}`; отпускание → `listen{state:stop}`. Шлюз после M2 сам добирает фразу по `listen stop`.
- Вниз: бинарные кадры → `AudioDecoder({codec:'opus', sampleRate:24000, numberOfChannels:1})` → очередь `AudioBuffer`, которая играет без разрывов (планирование по `AudioContext.currentTime`). JSON `stt` и `tts` обновляют чат и статус.
- Если нет `AudioEncoder`/`AudioDecoder` с Opus (`isConfigSupported`) или доступа к микрофону, блок эмулятора показывает понятное сообщение, а остальная панель работает.

## 6. Ошибки

| Ситуация | Поведение |
|---|---|
| Мозг недоступен | шапка красная; ход эмулятора заканчивается `tts stop` (поведение M2), в ленте отмечен как ошибка |
| SSE оборвался | `EventSource` переподключается сам; после переподключения клиент перечитывает `/api/state` |
| Отставание SSE-подписчика | событие `resync` → перечитать `/api/state` |
| Запрос к панели или `/api/*` не с localhost | 403 |
| `?token=` для неэмуляторного устройства или не с loopback | 401 |
| WebCodecs не поддерживается | сообщение в блоке эмулятора, панель работает |

## 7. Тесты

- **Python:** `TurnRunner` в успешном ходе отдаёт `TurnEnd.timings`, где `stt_ms`, `llm_ms` и `tts_ms` не меньше искусственных задержек в фейках (`time.sleep` 20 мс); если STT упал или вернул пустой текст, `llm_ms` и `tts_ms` равны 0, а `stt_ms` отражает время попытки.
- **Rust, модульные:** `summary()` (медиана и p95 на известных наборах, пустой буфер), кольцевой буфер вытесняет 101-й ход, `TurnRecord` при прерывании получает статус `aborted`.
- **Rust, e2e:** после хода `/api/state` содержит ход с `transcript`, `reply_text`, `first_audio_ms > 0` и таймингами из `TurnTimings` фейкового мозга. `/api/events` отдаёт `turn_started` → `transcript` → `turn_end` для этого хода. `/api/emulator` отдаёт токен, и `/ws?token=` с ним проходит авторизацию. `?token=` для обычного устройства даёт 401. `GET /` отдаёт HTML.
- **Проверка в браузере:** открыть панель во встроенном браузере, убедиться, что события приходят при ходе py-xiaozhi или e2e-клиента. Эмулятор голосом проверяется вручную в Chrome.

## 8. Открытые вопросы

1. Поддержка `AudioEncoder` с Opus на 16 кГц в Safari на macOS пользователя: проверяется через `isConfigSupported`; если нет, эмулятор работает только в Chrome.
2. Нужно ли эмулятору автоматически переподключаться после перезапуска шлюза (для v1 достаточно кнопки «Переподключить»).
